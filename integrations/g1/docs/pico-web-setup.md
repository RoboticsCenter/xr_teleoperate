# PICO 网页准备

当前网络（2026-11-12）：电脑/PICO接收 `10.1.10.62`，G1 Wi-Fi `10.1.10.179`；PICO页面 <http://10.1.10.62:8027/>。以本地 `config/network.json` 和网页当前显示为准；下文旧 `.31` 地址属于迁移前记录。见[网络配置](network-config.md)。

电脑控制台保持 http://127.0.0.1:8025/ ，头显下载页保持 http://192.168.31.92:8027/ 。电脑 IP 固定沿用 192.168.31.92，准备按钮不修改网络设置。

控制台的「连接 G1」建立到 192.168.31.65 的只读 SSH 连接，核对已保存的机器人主机密钥，显示主机名、地址与连接状态。它不启动机器人控制器、手指服务或相机。「断开检查连接」只关闭这条检查连接，不会停止独立运行的手臂会话；机器人运动仍使用原 LAUNCH / START / STOP 控制。

校准区域的「检查 Head / Tracker 输入」会准备 PICO 服务与共享读取器，并持续显示当前所选手腕的实际输入。检查通过且没有活动输出时，校准采集按钮可用，不必连接 G1 或按 LAUNCH。原点需要有效 Head 和水平前向；后续三轴使用原点已记录的头部朝向。若读取器重启导致数据会话改变，需要重置本轮采集并重采原点。静止姿态仍然有效，成功检查不把旧数据永久视为可用。

1. 点击控制台的「一键启动 PICO」。它准备 APK 下载页、XRoboToolkit 接收服务、广播观测和共享 Tracker 读取；不启动手臂或手指输出。
2. 已安装 XRoboToolkit G1 Wrists 的头显可直接打开应用。新安装时，从页面打开安装页或下载双 Tracker APK。
3. 头显选择电脑 192.168.31.92，启用 Head、Object 双 Tracker 和 Send，保持应用前台。
4. 控制台分别显示下载页、接收服务、实际 IP 广播、Tracker 读取、头显网络连接、实时数据、Head 和左右腕 SN。网络已连接不等于收到有效姿态。
5. 需要方向/距离校准时，先结束手臂会话，再使用下方原点→前→左→上采集流程。只读采集不需要 LAUNCH。

LAUNCH 可以在没有 Tracker 数据时准备机器人；START 捕获中立姿态仍需有效 Head 和所选腕部。LAUNCH 会初始化机器人目标，STOP 会回位。没有新鲜数据时，网页会指出具体等待项，不要求 Tracker 必须持续移动。

「停止 PICO 接收」结束本页面拥有的接收服务与共享读取器，保留 APK 下载页；手臂会话运行时不能停止其输入。已由其他进程启动的接收服务不会被强行结束。外部下载服务通过固定 APK 的 `/sha256` 校验后复用，页面关闭不终止它。

接收服务重启后，如果头显没有自行重连，请重新选择同一电脑 IP。若显示机器人 SSH 不可达，需等待机器人电脑开机并恢复网络；这是与 PICO 输入独立的连接。

接口：`POST /api/pico/start {}`、`POST /api/pico/stop {}`；兼容原 `/api/services/pico/start|stop`。沿用本地控制 token 和 Origin 检查。`GET /api/status` 的 `services.pico_setup` 提供分层状态；构造和查询不会自动启动设备服务。

连接和输入检查接口：`POST /api/robot/connect {}`、`POST /api/robot/disconnect {}`、`POST /api/arms/input/check {}`。分别通过 `services.robot`、`services.arm_input` 返回状态。G1 只读连接与实际控制连接分开显示，输入检查本身不会采集或保存校准。
