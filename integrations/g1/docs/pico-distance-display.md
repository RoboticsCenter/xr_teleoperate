# PICO 实时腕部距离

当前网络（2026-11-12）：电脑/PICO接收 `10.1.10.62`，G1 Wi-Fi `10.1.10.179`；PICO页面 <http://10.1.10.62:8027/>。以本地 `config/network.json` 和网页当前显示为准；下文旧 `.31` 地址属于迁移前记录。见[网络配置](network-config.md)。

在头显浏览器打开 **http://192.168.31.92:8027/distance**。原安装页和电脑控制台的 PICO 面板也有入口。测距页面与 APK 下载服务共用端口8027，电脑控制台保持127.0.0.1:8025。

页面显示每只所选 Tracker 距测量起点的直线位移（厘米），以及向前、向左、向上的有符号分量；负号分别代表向后、向右、向下。这不是累计路程。方向冻结在设置测量起点时的 Head 水平朝向；安装偏移与原校准几何一致，不应用已保存的比例校正。

1. 在电脑采集校准原点后保持同一身体和手腕姿势，点击距离页面的「设置测量起点」。两处起点分别记录；本页不替换电脑校准原点。
2. 每个方向先回同一原点，再移动。页面显示电脑当前步骤及你填写的实际距离。大字 PICO 读数是未校正参考值，不是动作目标；不要等它达到你填写的距离才停止移动。
3. 原点需要 Head 与所选腕部有效输入。设好起点后，方向沿用冻结的 Head；单腕缺帧只隐藏该侧数据，输入会话或绑定改变后需要显式重新归零。

这些读数来自 Tracker 本身。**校准以你确认并填写的实际移动距离为准，可用实体尺确定**；不能用 Tracker 自己估计的距离来验证它自己的比例。

## 在 XRoboToolkit 内查看

测距服务同时提供1280×720中文距离画面，经指定仓库原 VideoBridge 转为2560×720双眼相同的 H.264 图像。没有开启机器人摄像头，摄像头驱动和手臂控制器均不参与。

保持 XRoboToolkit 前台，开启 Head / Object / Send。在 RemoteVision 中使用 **192.168.31.92、ZEDMINI、H.264、2560×720**，启动其 Listen/接收选项。图像源是上述网页的 `/distance.jpg`。本机显示服务监听13579，内部状态监听127.0.0.1:13581。

若进入浏览器导致跟踪暂停，先保持起点姿势并点击「等待输入后归零」，再回到 XRoboToolkit。下一组有效新输入会设为本页起点，可在等待期间取消。若点击时有效输入仍持续到达，归零会立即随下一帧发生，并不检测应用焦点。随后通过 RemoteVision 查看距离，避免切换应用。

## 服务与验证边界

- `unitree-g1-pico-page.service`运行`serve_pico_apk.py --pico-video`，拥有距离HTTP服务和原VideoBridge子进程。现有视频端口被其他相机服务占用时不会终止或替换它；网页测距仍可使用。
- 只GET电脑控制台的状态，读取已有共享Tracker文件，沿用原0.5秒帧新鲜度。构造不启动SDK、控制器、机械手或SSH。LAN页面只获得过滤后的测量状态与独立测量令牌，不暴露控制台令牌或任何机器人动作接口。
- POST仅允许`/api/distance/zero`、`/api/distance/arm-zero`、`/api/distance/cancel-zero`，只改变服务内存中的测量起点。重启该页面服务会清测量起点，但不重启电脑控制台或丢弃其校准草稿。
- Pillow提供中文距离JPEG，当前安装于`.venv-dashboard`；原视频桥使用已有PyAV/numpy。`vendor/xr_h2/head_camera/pico_video.py`未修改。
- 29项测距Python、24项页面状态、12项安装页管理、8项原视频桥测试通过。模拟浏览器验证了20cm、单腕失帧、会话变更和等待归零。LAN页面与JPEG已实读；头显内实际显示仍需操作者打开后确认，不能把本机验证当成头显验收。
